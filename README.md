## About

I’m an independent developer who likes finding gaps between what software **could be** and what users actually have access to.

A recurring pattern in my work is simple:

> **Find the gap. Understand it deeply. Build the better option.**

That might mean making a premium-quality utility more accessible, simplifying a complicated workflow, building infrastructure that does not already exist, or creating an entirely new foundation when existing solutions are not enough.

I care less about shipping the largest number of projects and more about leaving behind software that is **useful, understandable, maintainable, and difficult to break**.

# MINK

<div align="center">

### A programming language built around a simple idea:

## **Power should not require unnecessary complexity.**

</div>

MINK is my primary long-term engineering project.

The goal is not to replace every existing language. Instead, MINK is being designed as a **bridge between different strengths of modern programming languages** — combining approachable development with systems capability, safety, deterministic tooling, and a compiler architecture designed to grow into multiple domains.

The compiler is being built from the foundations upward:

```text
Source
  │
  ├── Lexer
  ├── Parser / AST
  ├── Semantic Analysis
  ├── Type Analysis
  ├── Ownership
  ├── HIR
  ├── MIR
  ├── Optimization
  ├── Backend
  └── Runtime
        │
        ▼
   Native Software
